# Deployment fix changelog

Scope: make the existing prototype deploy and run reliably on **Vercel (frontend) + Render (backend, Docker) + PostgreSQL/pgvector**. No features, pages, routes, models, migrations or demo data were removed or redesigned.

## Backend

| File | What changed | Why | How it fixes deployment | Potential impact |
|---|---|---|---|---|
| `backend/app/config.py` | `DATABASE_URL` normalisation (`postgres://`, `postgresql://`, `postgresql+psycopg2://` → `postgresql+psycopg://`); `cors_origin_list` (trims spaces and trailing `/`, drops `*`, de-duplicates); optional `CORS_ORIGIN_REGEX`; `ENVIRONMENT=production` checks that refuse a placeholder or <32-char `JWT_SECRET` and an empty `CORS_ORIGINS`; DB pool settings. | Render/Neon hand out `postgres(ql)://` URLs, which SQLAlchemy maps to psycopg2 (not installed), so the app crashed. A default JWT secret could reach production unnoticed. | Provider URLs work unchanged. Unsafe production configs fail at boot with a clear message that never prints the secret. | In development a weak secret only logs a warning, so local behaviour is unchanged. |
| `backend/app/main.py` | Calls `validate_runtime()` at startup; CORS uses the parsed origin list plus the optional regex and exposes `Content-Disposition`/`Retry-After`; new `GET /api/health/ready` (DB, pgvector, migration revision, demo data; 503 when degraded). `/api/health` is unchanged. | Deployments need a dependency-free liveness check and a readiness check for debugging. | Render's health check stays green while the DB warms up; `/api/health/ready` shows exactly what is missing. | None to existing routes. |
| `backend/app/database/session.py` | Postgres engine: `pool_size`/`max_overflow` (configurable), `pool_recycle=300`, `pool_timeout=15`, `connect_timeout=10`; `pool_pre_ping` kept. The SQLite fallback is untouched. | Managed Postgres drops idle connections, and an unreachable DB used to hang requests. | Stale connections are recycled; a DB outage returns a fast 503 and recovers by itself (verified by stopping and restarting Postgres). | None. |
| `backend/app/api/agent.py` | The SSE stream sends a `: keep-alive` comment about every 15 s. | Proxies can close quiet event streams. | The live agent activity panel keeps streaming through Render and other proxies. | The client ignores comment lines. |
| `backend/scripts/seed.py` | Rewritten as a **safe** CLI: applies Alembic migrations, seeds **only if the DB is empty**, `--reset` for an explicit wipe (drop tables + `alembic_version`, re-migrate, re-seed), `--reset --yes` required when `ENVIRONMENT=production`, Postgres advisory lock against double seeding. | The old script always dropped and recreated every table, outside Alembic. Running it at startup (as `docker-compose.yml` did) wiped all data on every restart. | Restarts never destroy data; a seeded DB is always at the migration head. | `python -m scripts.seed` no longer resets an existing DB. Use `--reset` for the old behaviour. |
| `backend/scripts/start.sh` *(new)* | Entrypoint: `alembic upgrade head` → optional seed-if-empty (`SEED_DEMO_DATA=true`) → `uvicorn` on `0.0.0.0:${PORT:-8000}` with `--proxy-headers --forwarded-allow-ips`. | One reliable boot sequence for Docker and Render; the host assigns the port. | Behind Render's proxy, the rate limiter sees real client IPs instead of treating every judge as one IP. | None. |
| `backend/Dockerfile` | `python:3.14-slim` → `python:3.12-slim`; runs `scripts/start.sh`; non-root `app` user with a writable `storage/`; Docker `HEALTHCHECK`. | 3.12 is the stable target; running as non-root is safer. | Image builds and boots with the migrate → seed → serve sequence. | None. The full suite passes on 3.11 and 3.12. |
| `backend/.dockerignore` *(new)* | Excludes `.env`, caches, `storage/` and tests from the image. | Keeps secrets and local data out of images. | Smaller, safer image. | Tests aren't in the production image (mount them to run). |
| `backend/alembic/env.py` | `include_object` skips the 5 hand-written raw-SQL indexes (HNSW, full-text GIN, composites) during autogenerate. | `alembic check` reported false drift for indexes defined outside the ORM. | `alembic check` is clean (no pending operations), so real drift is visible. | None. Migrations are unchanged. |
| `backend/.env.example` | Documents `ENVIRONMENT`, `CORS_ORIGIN_REGEX`, `SEED_DEMO_DATA`, `DISABLE_SCHEDULER`, `SESSION_TTL_MINUTES`, pool settings and `RATE_LIMIT_SCALE`, with accepted URL formats. | Several variables the app reads weren't documented. | Copy-paste-ready configuration. | None. |
| `backend/tests/test_deployment.py` *(new)* | 11 tests: URL normalisation, CORS parsing and preflight (allowed vs foreign origin), production JWT/CORS validation, `/api/health` and `/api/health/ready`. | Guards the deployment behaviour. | Suite goes from 50 to 61 tests, all passing. | None. |

## Frontend

| File | What changed | Why | How it fixes deployment | Potential impact |
|---|---|---|---|---|
| `frontend/src/lib/api.ts` | `normalizeApiBase()`: trims whitespace and trailing `/` or `/api`, adds `https://` if missing, so `…/api/x` is never `//api`. 70 s timeout (120 s for uploads) for Render cold starts. Distinct errors: `TIMEOUT`, `OFFLINE`, `NETWORK` (message names the API host and the exact origin to add to `CORS_ORIGINS`), `MISCONFIGURED` (HTML came back instead of JSON, meaning `VITE_API_URL` is missing), and status-based messages for non-JSON 404/405/413/429/502–504/5xx. Console warning when a production build has no `VITE_API_URL`. The SSE parser handles `\r\n`. | The UI showed the same "Something went wrong" / "Can't reach" message for every failure. | Misconfigurations explain themselves in the UI (verified: missing `VITE_API_URL`, CORS-blocked origin, backend down, DB down). | All calls still go through the same central client. |
| `frontend/src/components/app/index.tsx` | `ErrorState` shows a heading per error code plus a small `CODE · HTTP n` line. | Makes failures tell-apart-able while debugging. | — | Visual only, in error states. |
| `frontend/src/features/agent/AgentPage.tsx` | The polling fallback now also runs when the stream **ends without** a final `run` event (not only on stream errors), and retries quietly if the backend is briefly unreachable. | A proxy closing the stream early would leave the activity panel "working" forever. | The agent panel always completes. | None. |
| `frontend/vite.config.ts` | The dev proxy (`/api` → `VITE_API_PROXY` or `http://localhost:8000`) is shared with `vite preview`. | `npm run preview` of a local build had no proxy. | — | Dev/preview only; production uses `VITE_API_URL`. |
| `frontend/vercel.json` | Keeps the SPA rewrite; adds framework, build and output settings and cache headers (immutable `/assets/*`, `no-cache` `index.html`). | Explicit build settings; new deploys aren't served stale `index.html`. | Deep links work, and each deploy's new bundle loads immediately. | None. |
| `frontend/.env.example` | Explains `VITE_API_URL` (public, build-time, trailing slash tolerated) and `VITE_API_PROXY`. | Clarity. | — | None. |
| `frontend/.dockerignore` *(new)* | Excludes `node_modules`, `dist`, `.env`. | Keeps builds clean. | — | None. |
| `frontend/tsconfig.tsbuildinfo` *(removed)* | Generated TypeScript build cache deleted from the package. | Generated file. | — | Recreated by `npm run build`. |
